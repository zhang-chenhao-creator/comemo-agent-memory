# 常见问题

## comemo 是什么？

comemo 是一套面向 coding agent 的 Markdown 记忆结构。它把记忆拆成全局规则、项目记忆和个人长期记忆三层，让 Agent 在正确的时候读取正确的上下文。

## comemo 是安装器吗？

不是。comemo 的核心流程不提供 `.sh`、`.ps1`、`.py`、二进制安装器或包管理器安装方式。安装应由 Agent 读取安装文档后，先检查现有文件，再安全创建或适配 Markdown 文件。

## 为什么不用全自动记忆？

因为全自动记忆容易把临时事实、项目状态和长期偏好混在一起，最后变成越来越厚、越来越难维护的上下文。comemo 更强调半自动：人和 AI 一起判断什么值得沉淀，再压缩成真正有长期价值的规则或背景。

## 为什么要分三层？

- 全局层：所有任务都应该稳定生效的硬规则。
- 项目层：当前项目的事实、流程、记录位置。
- 长期层：跨项目长期有效的偏好、目标、能力、经验、身份。

这样可以避免把项目临时状态写进全局记忆，也避免每次任务都默认加载完整个人背景。

## 为什么不把所有记忆写进一个文件？

一个大文件短期方便，长期会变慢、变乱，也更容易让 Agent 读取无关信息。comemo 使用路由表，让 Agent 按任务读取相关文件，而不是默认全量读取。

## 已经有 Claude Code、Cursor、Aider 或 Gemini CLI 的记忆文件怎么办？

默认不要重写。已有原生记忆文件应视为用户资产。comemo 推荐轻量桥接：让原生文件指向共享 `AGENTS.md`，或只给出合并建议，不复制完整记忆系统。

## `AGENTS.md` 可以改名成 `AGENT.md` 吗？

不建议。comemo 固定使用 `AGENTS.md` 作为 Codex 风格指令文件名。

## 可以把 API key、token、密码写进长期记忆吗？

不可以。不要把密钥、API key、密码、私有 token、金融凭据或高度敏感的个人信息写进 comemo 记忆文件。必要时先脱敏。

## 项目实验数据应该写在哪里？

写在项目目录内的记录文件中，例如 `records/experiment-record.md`，不要写入全局层或长期个人记忆。

## comemo 保证兼容所有 coding agent 吗？

不保证。comemo 是 Markdown 模板和轻量适配示例，不是运行时集成层。不同工具的行为可能随版本变化，兼容性说明应定期复查。
